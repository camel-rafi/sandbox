# sandbox

협업 흐름·Discord 알림 테스트 및 PR 연습용 저장소입니다. 이슈, 브랜치, PR을 자유롭게 만들고 지워도 됩니다.

camel-rafi 조직에서 코드 관리, 작업 관리, 알림을 어떻게 할지 제안하는 초안이에요.

---

## 1. 코드 관리

### 권한

| 역할 | 할 수 있는 것 |
| --- | --- |
| Owner | 조직 설정, 멤버 초대, 저장소 생성, 웹후크 관리 |
| Member | 모든 저장소 읽기·쓰기, 브랜치 생성, 이슈·PR 작성, 리뷰, 병합 |

### main 브랜치에는 PR로 반영해요

main 브랜치는 GitHub 설정으로 보호되어 있어서, 직접 푸시하면 거부됩니다. 브랜치에서 작업한 뒤 PR로 합치면 돼요.

```
브랜치 만들기 → 커밋·푸시 → PR 열기 → 리뷰 → 병합
```

**브랜치 이름**은 `종류/짧은설명` 정도면 충분해요. 이슈가 있다면 번호를 넣어도 좋아요.

| 종류 | 용도 | 예시 |
| --- | --- | --- |
| `feature/` | 새 기능 | `feature/login-page` |
| `fix/` | 버그 수정 | `fix/signup-error` |
| `docs/` | 문서 | `docs/update-readme` |
| `chore/` | 설정, 정리, 기타 | `chore/update-gitignore` |

**터미널에서 작업할 때**

```bash
git switch main
git pull                            # 최신 main 받기
git switch -c feature/login-page    # 작업 브랜치 만들기

# 작업 후
git add .
git commit -m "로그인 폼 추가"
git push -u origin feature/login-page
```

푸시하면 저장소 페이지에 **Compare & pull request** 버튼이 나타나요.

**PR을 열 때**

- 무엇을, 왜 바꿨는지 간단히 적어 주세요.
- 관련 이슈가 있으면 설명에 `Closes #12`처럼 적어 보세요. 병합될 때 12번 이슈가 자동으로 닫혀요.
- 오른쪽 **Reviewers**에서 리뷰어를 지정하고, 승인을 받으면 병합한 뒤 **Delete branch**로 브랜치를 정리합니다.

## 2. 작업 관리

작업은 GitHub 이슈로 관리해요. 이슈는 누구나 만들 수 있고, PM이 이슈를 만들어 담당자를 지정해 줄 수도 있어요. 간단한 수정이나 금방 끝나는 일은 이슈 없이 바로 진행해도 괜찮아요. 담당자로 지정된 이슈는 오른쪽 Assignees에 이름이 표시되고, 내가 맡은 일은 Issues 탭에서 `assignee:@me`로 모아 볼 수 있어요.

### 프로젝트 보드

이슈는 조직의 [프로젝트 보드](https://github.com/orgs/camel-rafi/projects)에서 한눈에 볼 수 있어요.

| 열 | 의미 | 옮기는 방법 |
| --- | --- | --- |
| Todo | 아직 시작하지 않은 작업 | 이슈를 만들면 자동으로 들어옴 |
| In Progress | 진행 중인 작업 | 작업을 시작할 때 직접 옮김 |
| Done | 완료된 작업 | 이슈가 닫히거나 PR이 병합되면 자동으로 이동 |

## 3. Discord 알림

GitHub에서 일어나는 일이 Discord **#github-알림** 채널로 자동으로 올라와요.

| 알림이 오는 일 | 알림이 오지 않는 일 |
| --- | --- |
| 이슈 생성, 닫힘, 다시 열림 | 프로젝트 보드에서 카드 옮기기 |
| PR 생성, 병합, 닫힘 | 일반 커밋·푸시 |
| PR 리뷰 (승인, 수정 요청, 댓글) | |

알림에 대해 이야기할 게 있으면 해당 메시지의 **스레드**에서 이어가면 돼요.
